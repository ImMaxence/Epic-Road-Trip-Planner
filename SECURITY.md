# Security

## Reporting a vulnerability

Please report vulnerabilities privately through the [contact form on mbonnici.fr](https://mbonnici.fr/fr/contact)
(see also [`/.well-known/security.txt`](https://tripplanner.mbonnici.fr/.well-known/security.txt)). Do not open a public issue.

## Security model (v2.0.0)

| Area | Measure |
|---|---|
| Accounts | Visitors have **no account**: their trips and favourites live in their browser, share links carry the trip in the URL. The database stores administrator accounts and curated trips only, so there is no sign-up to abuse and no personal visitor data to leak. |
| Authentication | Administrators only: Google OAuth 2.0 authorization code flow with PKCE and a signed, single-use `state` cookie (10 min). ID tokens are verified server-side (`email_verified` required). No passwords exist. |
| Authorisation | Restricted to `ADMIN_EMAILS` (exact e-mails or `@domain`), deny by default; nothing is stored about refused addresses. The list is re-checked on every request: removing an address revokes its session immediately. |
| Sessions | HS256 JWT (≥ 32-byte secret generated by Coolify) in an `HttpOnly`, `SameSite=Lax`, `Secure` (over HTTPS) cookie; server-side version check allows revocation. |
| CSRF | SameSite cookies + `Origin` check on every state-changing API request; JSON-only bodies. |
| Access control | All writes require an administrator session. Private trips answer 404 to anyone but their owner. Share links are decoded defensively (size cap, strict types, unknown fields dropped). |
| Input validation | zod schemas on every endpoint (coordinates, INSEE codes, dates, sizes); 200 kB body limit; parameterised SQL (Drizzle); escaped `LIKE` patterns. |
| Output | React escaping; map popups built with escaped text; external links limited to `http(s)` on both server and client; `dangerouslySetInnerHTML` only for a static theme bootstrap and the QR code SVG generated locally from the share URL. |
| Abuse | Per-IP rate limits: 1000 requests / 5 min overall, routing 40/min, places 90/min, admin sign-in 30 / 15 min; 500 trips per administrator. Anonymous visitors cannot write to the database at all. |
| Headers | CSP with no third-party origin (`frame-ancestors 'none'`, `object-src 'none'`), HSTS, `X-Frame-Options: DENY`, `nosniff`, strict `Referrer-Policy`, `Permissions-Policy`, COOP. |
| Privacy | No cookie for visitors. No third-party script or request from the browser: map tiles/styles/fonts are proxied and cached by nginx, Google sign-in is a redirect. Request logs keep method, path and status only (no headers, cookies or bodies). |
| Data refresh | Administrators only, through the backend; the geo service additionally checks a shared secret (`SERVICE_PASSWORD_GEOADMIN`, constant-time comparison) and never runs two rebuilds at once. |
| Infrastructure | No published ports besides the web container; backend and geo service run as non-root users; secrets only in environment variables; MariaDB reachable on the private network only. |

## Audit — 2026-11-15

- **Dependencies:** `npm audit --omit=dev` → 0 vulnerabilities (backend, frontend); `pip-audit` → 0 (geo service). Four *moderate* advisories remain in `drizzle-kit`, a development-only tool not shipped in images.
- **Automated tests:** absence of sign-up/guest endpoints, session forgery, cross-origin writes, ownership of trips, open redirects, OAuth state replay and mismatch, admin list enforcement and revocation, malformed share links (Vitest + MariaDB, Playwright).
- **Black-box checks:** no `.env`, `.git`, server bundle or source map exposed; tile proxy cannot be pointed at another host; no CORS headers; `TRACE` refused; nginx version hidden; no duplicated security headers.

### Known residual risks

- `script-src` keeps `'unsafe-inline'`: the pre-rendered pages embed React Router hydration scripts inline. Mitigated by React escaping and the absence of user-controlled HTML.
- Routing uses the public FOSSGIS OSRM servers by default (fair use, best effort, cached 24 h and rate-limited here). Set `OSRM_CAR_URL`, `OSRM_BIKE_URL` and `OSRM_FOOT_URL` to self-hosted instances for heavy use.
- Administrator sessions last 30 days; revocation happens by removing the address from `ADMIN_EMAILS`.
- Data saved on a visitor's device is only as safe as that device; the site says so and offers export/erase.
- The 2024 code base committed a Thunderforest API key to the Git history; it is no longer used and should be revoked on the Thunderforest dashboard.
